## Proposed surgical changes, not yet in production

1. Backup staging: follow existing archive restore primitive; preserve Scope::Author, absolute path checks, exclusive publication and result type. Ensure copying/validation does not mutate active world. Verify error paths and interrupted saves before adjusting startup migration behavior. No destructive downgrade.
2. Focused network paths: retain original active_network authorization predicates. Select endpoint-specific CTE (fact table INDEXED BY network_subject, exact revision join, eligible lineage and existing withdrawal clause), apply kind/subject/interval, keep ORDER BY id LIMIT. For bidirectional incident reads use two endpoint-specific CTE arms, UNION (not UNION ALL), single ORDER BY id LIMIT 501; repeat auth on each original fact. Consider avoiding SQL duplication with only one small internal helper once the native query plans justify it. Do not force one index across all network operations.
3. BH-01: use focused outgoing traversal with bounded work; reuse canonical existing exact date/source resolution and deterministic graph order. Separate conservative whole-history cycle write check from returned historical active view. A localized read must not accidentally replace the stronger write invariant. Treat validation of existing corrupt unreachable components as a separate archive-integrity concern before changing semantics.
4. BH-03: focus by outgoing identity_redirect; do not count unrelated incident facts. Keep raw budget and check multiple visible eligible targets, no premature truncation. Apply same strategy to succession only after tests for occupied/ambiguous titles.
5. Shared branch context and expensive IPC: label unsupported areas immediately, then explicitly integrate them under current Phase 3–8 owners. Profile controlled read work and lock contention; do not create another storage authority or increase timeouts.
