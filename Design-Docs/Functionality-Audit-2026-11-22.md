## New high-value functional findings

F-01 (P0) Shared operational context: current metadata branch selector deliberately local to network studio. workspace.rs snapshot and query request types use main/day/revision, layout save/preview denies non-main in store/entries.rs, public_entry uses latest main publication. Preserve existing explicit capability denials rather than pretend branch support. Extend only verified read/write contexts, test one branch fact across graph/query/Canvas and publication policy. Related UX-01/10, #4/#5/#8/#72.

F-02 (P0) Stale-create and person-date consistency: workspace.rs RelationshipInput contains world/day/subject/target/kind/trust/tags but no expected_revision; author-workspace.ts sends context including expected_revision, backend create_relationship reloads latest world and commit pins that latest number rather than caller revision. workspace_create_person IPC accepts name/world only and creates ValidInterval::default; typed Store::create_identity starts at selected view.day. These are confirmed source differences, not evidence of corrupted user data. Need explicitly decide timeless vs dated person creation, expose same semantics and guard both creation commands with expected view revision where required. Reproduce stale revision after competing write; reject or explicitly revalidate, preserve no partial changes. Test same selected day/person in both paths and honest unknown birth vs identity validity. Do not equate identity start with biological birth. #4/#8, shared INV-03/10.

F-03 (P1) Complete lifecycle and evidence entry: generic Store mutations support correction/state but desktop registered workspace commands expose specialized create/event/relationship/definition/alias/claim workflows, not a general typed identity correction editor. No standalone general-source creation command in reviewed registrations; event/evidence forms create source records implicitly. Need source entry workflow, dated label correction vs later state, ending vs withdrawing facts, copy/select stable references and revision history. Preserve past author history; no implementation of destructive deletion to satisfy a lifecycle checkbox. #4/#6/#7.

F-04 (P1) Query-to-graph parity: query.rs exposes WithinPlace to Rust, not PredicateInput or a dedicated registered workspace containment query. 22 canonical kinds vs main 10-kind selection; projectScene only person/interpersonal bonds/events. Network, family, spatial and concept facts have separate read APIs; no complete focused graph backed by their original semantic IDs. Expose compatible operations with stable context, no competing graph model. Check 50k world focused neighborhood and typed filter replay; no unbounded global scene. #4/#6/#68/#72.

F-05 (P1) Bound component-to-reader parity: layout.rs validate_publication and compile restrict Query/SavedQuery/FamilyTable/NetworkTable/ImpactTable to author. This is intentional fail-closed, not a security defect. AT-19/22 cannot be treated complete by author-only table test; implement only explicitly authorized projection with source and edge visibility and no existence/count leakage. Publish permitted membership rows after canonical mutation then revoke and compare public search/backlinks/export. #5/#8.

F-06 (P1) Core calendar integration: backend register_calendar/normalize/date_on/uncertain EventDate, frontend exact normalized integer day on key event forms. Need calendar selection, input normalization, uncertainty preview and recorded vs effective time; maintain existing raw day for diagnostics. #4/#7/#8.

F-07 (P1) Query-first scale: 2,000-object snapshot cap in workspace.rs::snapshot and editorForms hidden for scene_limited in author-workspace.ts; current 50k Store and query benchmarks do not establish interactive editing at 50k. Focused per-entry read/write for supported commands and explicit operation limits for others. Do not just raise cap. Merge independent recovery optimization only after preserving its passing parity and consolidating protected migration. #4/#10.

F-08 (P1) Portable release: archive CLI exists, no regular archive UI; bundle.active=false. Need choose source/destination safely, verify manifest/hashes, never overwrite live data, preserve recovery copy, report unsupported newer schema, verify close/reopen and actual offline launch on target. #10.
