# Phase 3 — Authorized entry text search

Status: implemented on development branch; validation pending. Tracks [Phase 3 #4](https://github.com/sdhaight1-hash/ConWorld-Tools/issues/4) and [Phase 4 #5](https://github.com/sdhaight1-hash/ConWorld-Tools/issues/5). Baseline `e48368f25bf75162c8647ffefac5599e71038567` (#49, stacked on #48).

## Contract

QRY-03, INV-15, AT-20 and AT-25 (partial). The persisted entry and its existing Rust Display projection are the sole authority. Search a single entry's compiled text blocks, not raw layout JSON, canonical labels, query-backed author rows, or FTS author documents. An unpublished or inaccessible entry returns no page, while a visible page with no matches returns an empty match list. Match ordering follows layout order. Case-insensitive literal substring matching; no ranking, regex, arbitrary SQL, graph counts, or hidden snippets. Stable element IDs identify matching blocks. Trimmed query length 1–256 bytes; 1–50 returned blocks, explicit truncation, existing layout depth/element/text bounds. No migration or cached results. Reader revision must be current, so unpublication invalidates subsequent reads, including after restore. Public IPC fixes scope at the trusted host and always resolves latest revision; the author editor exposes a reader preview with request-generation protection against stale responses. Character-specific global search and public query bindings remain unsupported. This is not a new global search index or a completed AT-25 gate.

## Validation

Additional integration coverage verifies visible-only result budgets and ordering, Unicode case matching, reader-specific blocks and other-character denial. A mock-native Playwright regression covers current public IPC, superseded response rejection, no matches and unpublished entries, with optional correctly labeled screenshot capture. Native desktop exposes search from the existing character page editor. Run `cargo fmt --all -- --check`, `cargo test -p atlas-store --test roadmap_foundations`, strict workspace Clippy, frontend build and native smoke. ## Global public page search extension

The initial reader search's Rust CI passed on c8d0777; desktop CI failed the launcher manifest/handler/capability consistency test (run 44948557849). Both new command permissions are now explicitly registered, without broadening window access.

The same Rust text matcher now supports world-wide public page search from the workspace. The query fixes public scope and the latest author revision, selects only the latest released pages with public roots, then resolves each entry at the selected historical day and compiles the ordinary Display projection in a single SQLite read transaction. No author names or raw layout JSON leave Rust. Order is stable entry ID then layout order. At most 50 matching blocks; truncation is triggered only by additional visible matches. A 512-visible-page work ceiling and existing cancellable query-job deadline bound the initial nonindexed implementation; exceeding the work ceiling returns an error, not incomplete results advertised as complete. SQLite can still spend time scanning old layout rows; the progress handler interrupts that work. This is not constant-time authorization or an indexed publication corpus. Character-specific global search and externally distributable reader hosts are deferred. The reader preview re-resolves the selected entry before displaying and invalidates results on context changes, query input, and cancellation. Tests cover published/draft/hidden roots, historical day, world isolation, visible-only limits, revocation, cancellation and native-IPC mock navigation. CI must pass on the updated head; optional browser captures are explicitly mock-native.
