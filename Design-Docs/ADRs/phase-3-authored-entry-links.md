# Phase 3/4 — Authored object links and historical backlinks

Status: core implementation, validation pending. Tracks #4 and #5, LNK-01, INV-13/15, AT-20/25. An ObjectLink holds its stable ElementId, world-scoped target and authored caption. It is a presentation reference, not an inferred semantic edge. Author visibility resolves the canonical target at day/revision. Reader visibility requires a released destination page with a root visible to the same reader, at the latest reader revision and selected day. Unavailable destinations remove the whole link, including caption and ID. Destination layouts are never recursively compiled. Reader display holds a single SQLite snapshot for source and destination.

Schema 26 materializes versioned source/element/target keys transactionally alongside layout versions. Captions and audience remain canonical layout data. Reverse lookup reselects the latest source version at the requested revision, applies source release, inherited audience and destination policy, emits only authorized references in stable source/layout order; limits 1–50 and cancellation, truncation only on extra visible matches. Existing semantic backlinks remain separate. Timing is not constant-time. Migration and existing rebuild regenerate links. Current public text FTS intentionally excludes destination-dependent captions until target-aware reverse invalidation is designed. UI and link spans/hotspots remain future slices. Integration regression covers cyclic links, publication/withdrawal, hidden subtree, truncation, historical deletion and rebuild. No visual capture claimed.
