# Phase 4 — Grid and Panel layout containers

Tracks #5/#4 CAN-01, INV-13/15, AT-17–20 and AT-25 (partial). Add two real persistent element variants and compiled equivalents. Root remains Stack; Grid accepts 1–4 columns and ordered children, Panel accepts ordered children. Shared validation, subtree publication checks, caption candidates, text indexing, authored backlinks and result traversal all recognize both. Reparenting through any of the three containers retains stable element IDs, saved/inline bindings and effective audience restrictions. Hidden containers are pruned before projection; private queries are never executed by public compilation. Column count is explicit author layout metadata, not a count of hidden children. No duplicated semantic fields or changed IPC. Schema 28 guards new serialized variants; layout schema 1 remains backward-compatible with prior serialized Stack documents, no DDL.

Reader and author preview render real nested containers, and the existing flat editor has a deliberately narrow arrangement control that wraps its supported body/notes/query/link blocks in one public Grid or Panel, or unwraps to Stack. Existing wrapper and component IDs persist across Grid/Panel changes; unsupported deeply nested shapes remain read-only in this editor rather than being flattened or overwritten. General tree authoring, arbitrary component placement, responsive tracks/spans and reusable templates remain future work. Browser grid uses bounded columns and collapses on narrow viewport.

Regression covers invalid columns, reparenting an author-only query into a public Grid without broadening audience, persisted public caption and body search, hidden text, backlinks and rebuild. Mock-native browser test changes Grid to Panel and reopens, checks stable identities and authorized render; configured actual screenshot capture. Full CI pending.
