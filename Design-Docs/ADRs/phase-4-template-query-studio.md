# Phase 4 — Versioned templates and dynamic author components

Tracks #4/#5/#6/#7/#8. Built-in immutable v1 template catalog for blank, character, family, organization, event, conflict, location, genealogy and source entries. Template instances persist as a typed Template container with exact key/version and independent child IDs. Unknown version fails validation. Template projection uses Panel and all existing visibility, static text search, link indexing and reparenting walkers recognize its children. Schema 29 protects new serialized variants. Templates insert presentation sections without modifying existing objects or layouts; instances never auto-upgrade. User-authored template library/version migrations remain future work.

Canvas tree supports creating multiple saved query components, selecting a pinned definition revision, retrieving earlier definition revisions, and editing typed per-component overrides. It never widens query privileges: queries remain author-only and Rust validates binding and release. Existing query pins survive movement and reopen. Historical author components use existing typed ParticipantEvents and EventRole filters with entry identity, not copied scene data. Character/event templates include their corresponding historical query. Wrong-kind target errors are validated through Rust query execution; no automatic claims or relationships created. Other templates provide editable presentation sections, not implemented domain widgets. Reader-safe dynamic queries require an authorized result engine and are not enabled here.

Rust regression covers template version validation, nested query publication refusal, private projection, persistence and historical revision. Playwright mock-native regression covers insertion and multiple independent query overrides with pinned IDs, save/reopen, screenshot configuration. Stacked on #57, verification pending. No claim of native runtime success.
