# Phase 3/4 — Version-pinned saved-query layout bindings

Status: implemented core; CI pending. Tracks [Phase 3 #4](https://github.com/sdhaight1-hash/ConWorld-Tools/issues/4) / [Phase 4 #5](https://github.com/sdhaight1-hash/ConWorld-Tools/issues/5). Stacked on #50. Relevant QRY-02, INV-13, INV-15, AT-18, AT-22, AT-34 (partial).

A private layout component can reference one stable saved-query ID, its actual recorded definition revision, its world and typed parameter bindings. Resolve the exact historical definition and call the existing SavedLabelQuery::bind then the same Rust QuerySpec executor used by Node. The layout's data view is not pinned to the definition's revision: edits to world facts appear on the next compilation, while an older author view can reproduce prior results. Revising a saved definition does not silently change existing layout meaning; explicit rebinding is required. A definition pin must refer to an actual saved revision, not an arbitrary later snapshot. No stored results or separate query engine.

Existing Query and SavedQuery components share the same 16-query projection budget. Both are author-only; release validation rejects a query in any reader-accessible subtree and the public projection skips hidden subtrees before resolving bindings. Reparent preserves stable element ID and inherited restrictions. The public candidate index also excludes query bindings. Schema 25 is a DDL-free compatibility bump to prevent older applications from opening new serialized layout variants; existing layout JSON remains valid. Backend initial slice only: the character-page editor does not yet author or inspect these bindings; public query-backed tables remain unsupported until a positive authorized data-source contract exists.

Integration regression: direct Node query parity, typed parameter override, exact pin/cross-world and reader refusal, reparent, persistence, correction, old author revision, revised definition independence, hidden public result and reopen. No UI screenshot claimed. CI pending.
