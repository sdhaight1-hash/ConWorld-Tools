A private layout component can reference one stable saved-query ID, its actual recorded definition revision, its world and typed parameter bindings. Resolve the exact historical definition and call the existing SavedLabelQuery::bind then the same Rust QuerySpec executor used by Node. The layout's data view is not pinned to the definition's revision: edits to world facts appear on the next compilation, while an older author view can reproduce prior results. Revising a saved definition does not silently change existing layout meaning; explicit rebinding is required. A definition pin must refer to an actual saved revision, not an arbitrary later snapshot. No stored results or separate query engine.

Existing Query and SavedQuery components share the same 16-query projection budget. Both are author-only; release validation rejects a query in any reader-accessible subtree and the public projection skips hidden subtrees before resolving bindings. Reparent preserves stable element ID and inherited restrictions. The public candidate index also excludes query bindings. Schema 25 is a DDL-free compatibility bump to prevent older applications from opening new serialized layout variants; existing layout JSON remains valid. The editor integration described below authors and inspects these bindings; public query-backed tables remain unsupported until a positive authorized data-source contract exists.

Integration regression: direct Node query parity, typed parameter override, exact pin/cross-world and reader refusal, reparent, persistence, correction, old author revision, revised definition independence, hidden public result and reopen. No UI screenshot claimed. Exact-head CI passed.

## Native character-page binding editor

The existing character-page editor now supports its two text blocks plus one optional private saved-query table. Select a saved definition/version, edit typed parameter values, preview the unsaved draft in Rust, then save the same stable component identity and binding. If a saved definition has been superseded, the editor explicitly retrieves the historical pin and keeps it selected rather than silently updating it. A pinned author revision remains read-only; preview uses that historical view. Unsupported layouts are not rewritten. The preview IPC fixes scope to Author, checks world/main branch/revision/entry, enforces the existing layout and serialization bounds, and runs in the existing cancellable query-job path; it is separate from the persisted reader projection. No draft is published or persisted by preview. Public preview/search continue to use the existing reader IPC. Added Rust nonmutation/reader-denial assertions, mock-native editor regression and optional screenshot artifact. This is one private table, not a full component editor or safe public query source. Exact-head CI passed.
