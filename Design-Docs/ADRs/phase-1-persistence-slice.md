# Phase One persistence baseline

**Scope:** [Phase One #2](https://github.com/sdhaight1-hash/ConWorld-Tools/issues/2), first implementation slice. [Phase Zero #1](https://github.com/sdhaight1-hash/ConWorld-Tools/issues/1) still requires a Windows desktop and WebGPU/fallback proof.

- **ADR-001, initial revision semantics.** A world starts at revision 0 on a stable root branch. A command appends one world-scoped revision and full object versions atomically. A read chooses the most recent version at or before the requested author revision, then evaluates its half-open valid interval. This order prevents a corrected interval from resurrecting an obsolete version. This slice stores one assertion interval per object version. Multiple dated states, fork creation and parent overlays remain open.
- **ADR-003, initial time representation.** The store accepts signed, normalized world days and optional interval endpoints. Event occurrences may be exact, unknown or uncertain with labeled inclusive bounds. An occurrence's three-valued day match is independent of the record's half-open valid interval. Calendar registration, conversion and dataset-wide uncertain fact queries remain open.
- **ADR-005, initial authorization boundary.** The facade is intended for the trusted local author process. Every record read takes an explicit world, root branch, author revision, fictional day and scope. Public scope is denied before storage queries. Actor identities are audit metadata supplied by that process. IPC capabilities and perspective policies remain open.
- **ADR-006, migration and backup.** Bundle SQLite through rusqlite. Apply migration 0001 and update `user_version` in one immediate transaction. A newer schema is refused. The migration introduces the first production tables for this repository. Earlier prototype databases require an explicit import path. Use SQLite's `VACUUM INTO` for a standalone database snapshot and require a new destination file.
- **ADR-007, initial registry.** Stable UUIDs carry their world. Registry kinds are closed in this slice, with checked, typed columns for event occurrences and source citations. Evidence references live on object revisions. Source references must resolve to an existing source in the same world at the time of the command, including sources authored earlier in the same batch. Future custom types and claims require separate validation and storage decisions.
- Commands use an expected world revision and a unique command UUID. An already committed UUID produces a distinct duplicate-command error. Failed batches roll back both the audit row and the invalidations. Derived readers can build from the committed invalidation records when they are introduced.
