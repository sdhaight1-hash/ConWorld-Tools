# Phase 3/4 — Destination-authorized caption search

Tracks #4/#5, QRY-03, LNK-01, INV-10/15 and AT-20/25 (partial). Assumes a link caption belongs to the compiled ObjectLink, not a semantic fact or independent public record. The same canonical Display matcher now searches text and authorized link captions in layout order. No new UI IPC or query type: existing page/global reader search consumes the same result DTO and stable element ID. Author and character page search use their own compiled view; global remains public/current/main only.

Schema 27 keeps destination-dependent captions out of the static public-text corpus. Separate internal trigram candidates are materialized only for the current released source's public subtree. Each candidate retains world, source layout revision, element and target. Source updates and withdrawals replace candidates atomically with the layout. A query unions public text candidates with matching captions whose source and target have current public-root release rows, then rereads and compiles each source in one SQLite read snapshot; only compiled visible blocks can produce results. Publication of a destination may make an existing caption searchable without a source edit; withdrawal removes it immediately. The target's effective day is checked by compilation. Short/NUL queries use the existing all-released-source fallback. Hidden caption-only false positives never consume the 512-visible-page budget; raw SQL and compilation remain subject to cancellation/deadline, not constant-time guarantees. Candidate rows are not a public export. Migration and explicit rebuild regenerate both indexes from the latest source layouts.

Regression added for linked-only page, Unicode/quoted and two-character search, hidden ancestor, unpublished/future/withdrawn/re-released target, historical author access, stable element, schema-26 migration, explicit rebuild and source removal. A local SQLite 3.46.1 smoke passed trigram matching, target release gating and candidate deletion; Rust and desktop CI pending. No native UI capture claimed. Image hotspots, arbitrary rich-text spans, ranking and scale acceptance remain open.
