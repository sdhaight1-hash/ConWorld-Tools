## 1. Executive conclusion

The project has a credible local-first historical authoring foundation. Rust owns identity, fictional time, author revisions, transactions, claims, explicit effects and read semantics; Tauri/TypeScript presents the author workspace. The strongest subsystem is temporal integrity. The main strategic risk is accumulating increasingly elaborate backend search slices before delivering one coherent, authorized Node → Canvas → Display entry. Do not rewrite the stack or split it into speculative crates; first close the current Phase 3 integration chain and the minimum security/behavior gates needed by Phase 4. Later-phase modules are executable foundations, not shipped studios or completed domains.

**Method and limitations.** Enumerated complete, non-truncated recursive trees: 130 files on the pinned main tree, 137 on the staged tree. Compared the two trees (20 changed paths, 49 commits ahead by ancestry including reconciliation commits). Reviewed the normative design document set, README, implementation/verification logs, relevant ADRs, roadmap issue bodies/states/checklists, core Rust modules, migration inventory and DDL, query planner/cache, native IPC and host setup, frontend interactions, renderer, CI configurations and test inventory/logs. Examined selected high-risk implementation paths in depth. This is a repo-wide static/code-contract and existing-CI audit, not an exhaustive line-by-line formal proof, dependency CVE scan, new physical-GPU run or penetration test. Direct container git clone was unavailable (DNS), and local Cargo was absent; exact-head GitHub Actions logs are the executable verification evidence. No claims of freshly executed local Rust tests.

## 4. Architecture and source review

### 4.1 Storage, domain and chronology

- [atlas-store lib.rs](https://github.com/sdhaight1-hash/ConWorld-Tools/blob/2741a15616317e20484340c845271b6167ea043f/crates/atlas-store/src/lib.rs): typed world/branch/object IDs, scope, version references, event uncertainty, explicit Change variants. Current canonical registry has person, definition, relationship, event involvement, actor action, historical event, source and claim; broad planned types are absent. Do not present generic relationships as persistent family/organization models.
- [store.rs](https://github.com/sdhaight1-hash/ConWorld-Tools/blob/2741a15616317e20484340c845271b6167ea043f/crates/atlas-store/src/store.rs): 3,605 lines at staged baseline, one authoritative transactional store; foreign key checks, optimistic author revisions, correction vs state recording, historical resolution, direct effects, derived indexing. Strong tests for nested branch inheritance and rollback. No explicit generic tombstone/delete/restore workflow; stable identity and valid-state history are good, but lifecycle contract remains partial.
- Migration coverage: 0001 registry/revisions; 0002 historical state; 0003 branch forks; 0004 calendar; 0005 claims/effects/calendar sources; 0006 relationships/involvement/actions; 0007 definitions/audiences; 0008 label FTS; 0009 saved queries; 0010 mention reviews; 0011 claim FTS; 0012 composite definitions; 0013 participation; 0014 aliases; version 15 is deliberately DDL-free saved predicate compatibility (not missing file); 0016 reverse endpoint; 0017 alias keys; 0018 backlinks; staged 0019 typed parameters, 0020 discovery kind/lineage, 0021 prefix expressions. No full archive assets, manifest hashes, import/merge or restore UI; backup may leave an incomplete file on process crash, so distinguish completed backup from partial file.

### 4.2 Search, paths, discovery and caches

[query.rs](https://github.com/sdhaight1-hash/ConWorld-Tools/blob/2741a15616317e20484340c845271b6167ea043f/crates/atlas-store/src/query.rs): typed allowlisted filter enums, upfront structural validation, bounded AND/OR/NOT, author-only execution, stable label+UUID ordering, indexed exact alias/FTS/roles/backlinks/traversal. Scope denial is currently a sound fail-closed measure, not published query support. Indexed positive text/alias leaves can narrow compound queries; unanchored Kind/HasSource/NOT/etc. still fall back to 2,000 visible objects and 10,000 registry scan. RelationshipPath is bounded and not paginated as a traversal. Page cursor binds exact spec/view and row boundary; each page reruns a bounded query up to 10k and drains prior rows. No true SQL keyset streaming or general planner/aggregation/interval/ranking/image indexing yet. These constraints should be shown in UX instead of implying unlimited search.

[discovery.rs](https://github.com/sdhaight1-hash/ConWorld-Tools/blob/2741a15616317e20484340c845271b6167ea043f/crates/atlas-store/src/discovery.rs): exact claim version/UTF-8 offsets, name versus alias provenance, distinct possible identities, review not inference, author scope. Staged #42 limits candidate kinds and adds claim focus; #44 versioned prefix expression indexes preserve exact matching (ASCII case-insensitive; exact Unicode casing), #45 single-slot complete nontruncated controlled preview (max 100 rows). Revision-delta consumer replaces affected source previews, conservatively full refreshes after name edits and context changes, preserves old historical views, clears after reindex. This is a small safe optimization, not a persistent corpus or universal materialized dependency graph. Fork alias/review semantics still main-only.

### 4.3 Native host and application UX

[workspace.rs](https://github.com/sdhaight1-hash/ConWorld-Tools/blob/2741a15616317e20484340c845271b6167ea043f/apps/desktop/src-tauri/src/workspace.rs): 2,899 lines; one storage mutex, native author commands, pinned query tokens, 8-job/admission cap, cooperative 10-second query controls, request cancellation outside store lock. Search-only scene fallback disables incomplete graph editing; staged focused discovery remains available. Historical revision pinning works, but main-branch context is implicit in native `view`. Author creates world/person/relationship and records event, tags/relationship corrections, aliases and claims. No general entity detail editor, full genealogy, calendar/branch studio, document builder or publication reader. [author-workspace.ts](https://github.com/sdhaight1-hash/ConWorld-Tools/blob/2741a15616317e20484340c845271b6167ea043f/apps/desktop/src/author-workspace.ts) is 1,342 lines and uses safe textContent/DOM construction, request sequences, keyboard buttons, historical form state. Scene is a simple grid of people/reified relationships/events; no persistent pin/layout, true focused editable subgraph, search-to-field editor, graph lenses, drag/drop or large-scene virtualization. Keep accessible result list, improve actual user workflow rather than cosmetic redesign.

[Tauri capability manifest](https://github.com/sdhaight1-hash/ConWorld-Tools/blob/2741a15616317e20484340c845271b6167ea043f/apps/desktop/src-tauri/capabilities/platform-shell.json) restricts commands to the main window; [tauri.conf.json](https://github.com/sdhaight1-hash/ConWorld-Tools/blob/2741a15616317e20484340c845271b6167ea043f/apps/desktop/src-tauri/tauri.conf.json) has restrictive CSP and loopback development URL. All current workspace operations intentionally execute with local author privileges, including author preview. A capability allowlist for one author window is not an audience boundary. Public/character readers must never inherit this command authority. No production Display window is currently claimed.

### 4.4 Renderer and platform

[Renderer](https://github.com/sdhaight1-hash/ConWorld-Tools/blob/2741a15616317e20484340c845271b6167ea043f/crates/atlas-renderer/src/lib.rs) builds wgpu/WASM for WebGPU; [main.ts](https://github.com/sdhaight1-hash/ConWorld-Tools/blob/2741a15616317e20484340c845271b6167ea043f/apps/desktop/src/main.ts) retains Canvas2D and keyboard controls, device-loss fallback/retry in benchmark; normal persistent graph still uses Canvas2D. The auto wgpu activation condition is benchmark-only. GPU vertex buffers are rebuilt on every draw; optimize only after real measurements, by reusing buffers and drawing the focused viewport. Earlier physical RTX 2060 benchmark in [Phase-0-Verification.md](Phase-0-Verification.md) recorded 2,000 nodes, 3,910 edges, 24 frame intervals, median 16.70 ms, range 16.60–16.80 ms, selected pixels and loss/recovery. That proves feasibility on that workload and build only. Latest Windows CI Hyper-V adapter unavailable; fallback passed. Linux browser GPU test skipped in ordinary run. `start.bat` starts Tauri dev with dependencies; it does not build WASM renderer itself. CI builds it separately. Packaging disabled, so current launch is developer-oriented, not an installer.
