## Executive finding

The engineering harness has become a single scrolling accumulation of feature controls. In the existing product charter, Node, Canvas and Display are complementary representations of one canonical identity. They are not yet equally usable workspaces. Existing HTML contains 14 literal form tags; the dynamically inserted network studio contains 15 more before additional editor-generated controls. This is a count of source tags, not a count of simultaneously visible forms. The normal shell has a maximum main width of 78rem, graph plus fixed 17rem inspector, 1080x760 default window, 460x540 minimum. The inspector hosts entire authoring and reader experiences; result rows often repeat several full-width actions. Focus should shift from adding more forms to completing the approved interaction architecture.

Preserve: current warm dark visual palette, explicit source/claim distinction, latest vs pinned read-only revision, stable identities and duplicate-name disambiguation, cancellation/late reply guards, Rust-owned access/validation, no-GPU fallback, private-first new components, version-pinned templates/query bindings and working accessible DOM alternatives. Do not replace Rust authority, introduce a second UI data model, change schema, add framework/dependencies or introduce new product scope merely to redesign the shell.

## Target interaction layout (proposal, not screenshot)

A small desktop workbench rather than a new engine. One persistent header: world, date, branch, revision, audience/capability, save status. Primary surface selector Node | Canvas | Display. Global author search remains a panel/palette, not another data source. Contextual create button offers current supported kinds. Left searchable outline/results optionally collapsible; center active workspace; right contextual properties/evidence inspector optionally collapsible. Node central graph/list/timeline tabs reflect same focus; families, events, locations, institutions and concepts are contextual routes or filters, not separate world databases. Canvas central live preview, component tree/palette and inspector; Display full reading surface, authorized links/backlinks/search only. Narrow windows use mutually accessible panels rather than compressing all three columns. Prefer normal DOM/CSS and current renderer. Preserve original control IDs/hooks as needed for safe incremental migration; no aesthetic rebuild of unrelated modules.

Do not put every tool on the main screen. Basic mode shows common task controls. Advanced filter AST, raw IDs, numeric budgets, diagnostics and developer benchmark remain discoverable on demand. A selected item should answer: what is it, what is connected, when, why/evidence, what can be changed at this context? Actions contextual to capability and selection. Expose original recorded fact IDs and distinguish claim/candidate from accepted canon; semantic profile is not a presentation template.
