## 1. Decision and method

Recommend one typed historical graph with stable independent identities, versioned controlled classifications, validated typed facts/attributes, distinct epistemic records and derived presentation. Start by completing already specified Concept, compatible domain endpoints, governed relationship definitions, reified fact references, evidence/knowledge and approved Place. The distinctly additional candidate is **world-scoped author-defined semantic profiles and constrained typed extensions** (classification/field/predicate definitions and lifecycle), with limited initial profiles for culture/language, material/technology, works and agreements. Assess a separate feature proposal after owner review; not all subjects need dedicated enum variants. No claim that every proposed profile is already original scope. Do not turn the entire domain into EAV/JSON or replace canonical genealogy, succession, event, conflict, spatial or scope validation. No automatic adoption of simulation mechanics.

Methods: refreshed pinned repository inventory, README policy, review, design docs 01/03/04/05/06/07/08/09/10/13, accepted #68/#70 and media indexes; re-inspected Rust/SQL/IPC/UI source sections cited below. This is whole-repository inventory and targeted ontology audit, not line-by-line review of unrelated code. Reopened comparative sources R1–R23 and extra official IFLA/VS/DF references; ACKS public Foundry files inspected at pinned SHA. No commercial rulebook purchased or fully read, no installed game/runtime trial, no proprietary schema claims for closed games. Source-derived findings distinguished from candidate Atlas representations and synthetic scenarios. Independently executed Python/SQLite comparison of normalized classification rows and version-qualified JSON arrays (section 7). No native usability or security proof, no UI capture applicable.

Working semantics: core kind answers identity/invariants, author profile answers useful field/relationship affordances, classification answers membership in vocabulary, event answers dated occurrence, fact answers a typed proposition with valid time/revision/source, claim answers reported proposition and knower model, layout answers presentation. Classification is not evidence of a relationship with a named organization or person. A category such as "smith" is not an employment record. Multiple contextual classifications may share an entity ID without implying descent, exclusivity or allegiance. No universal closed-world assumption: lack of evidence is not established; explicit negation/contrary claim requires recorded assertion; enforce closed cardinality only when declared and supported by canon.

## 5. Domain coverage and representation decision matrix

Key: E = existing original obligation or approved feature, P = possible distinct extension requiring feature approval where beyond original, D = defer/reject specialized engine. "Concept/profile" means referenceable authored concept plus controlled semantic profile proposed; classification vocabulary distinct from in-world concept. All candidate payload choices below are recommendations, not new enum or schema approval. Each row names lifecycle/relationship and competency question; executable subset §7, remainder analytical design questions with explicit desired answers. Every record/fact uses scoped world IDs and valid/revision/branch provenance, unknown optional values, claim/candidate separation.

| Work, edition, artwork, source, physical copy | Work Concept/profile and stable versions/expressions, optional edition refs, copy Asset if independently tracked, evidence Source pointing to exact source version; creator and copy owner distinct. | Who wrote work and which copy embodies it? separate; contradictory editions don't overwrite work. | P work/edition profile where useful; E source/asset/evidence; D full library catalog mandatory |
| Event, process, Conflict, issue/phase, reign/era | Existing Event/Action/Conflict; era Concept/period projection, correlated occurrence not automatic cause; transfer history or succession event vs authored correction. | Who held title on boundary day; event output vs hypothetical description? actual recorded facts. | E hierarchy, roles, effects and uncertain date |
| Claim, Source, belief, knowledge, rumor, definitions, authoring | Existing claim/source and governed definitions; provenance and independently addressable fact/qualifiers; separate knowledge acquisition; drafts, map/transform recipe, layout, saved query, generated projections not canon. | Fork claim King holds title not canonical; hide secret source and facts before result. | E original semantics, #70/#68 metadata as approved; P additional typed fields only if gap |

Shortlist explicit: Concept existing, Culture/Language/Species/BeliefSystem/Work/Technology/Commodity/Resource initial **classified concepts** not separate enums. Agreement/LegalInstrument may need specialized n-ary obligation payload, not blanket core kind. SocialGroup/Polity/Organism additional independent identity only after evidence they cannot be modeled using existing categories without losing key invariants. Prioritize by usefulness, constraints and actual queries, not number of named types. Profile names may vary by world; profiles are metadata constraints, not canonical assertion about object until explicitly classified. Example one Place may be town and administrative center, faith is Concept, church institution Organization, temple Place. Speculative deity can be actual agent or only myth, depending on canon. Law text Source, law concept/instrument, adoption event and obligation distinct.

## 6. Alternatives and logical architecture

| Model | Strength | Failure/cost and decision |
|---|---|---|
| Add one Rust/SQL kind per article category | Strong local contracts, explicit endpoints | Repeated migration, wire/selector/schema/query/editor/transform switches for mere synonyms; poor author extensions. Keep specialized kinds only for materially distinct validation/lifecycle. |
| Fixed typed core + controlled multi-classification rows | Stable IDs, multiple classification dimensions and qualified history, indexed query | New descriptor/version/constraint/addressability logic, need policy before query facets. Recommended first extension design; test compatibility with existing Concept and definitions. |
| Constrained typed extension fields and predicates | Captures richer authored domains without new enum for each field | Validation, migration/versioning and query indexing complexity. Limit declared datatypes/reference kinds, units and cardinality; no generic writes to protected core. Candidate new feature if distinct scope. |
| JSON profile documents with typed validation | Portable small attributes, easy schema inspection | Multi-valued historical filters and provenance expensive without indexes/derived projection; reject as sole source of arbitrary facts. Can use versioned JSON for definitions/layout where validated; compare prototype. |
| Unrestricted EAV, arbitrary RDF/OWL reasoner/runtime | Flexibility | Loses authoritative domain invariants and bounded policy; violates 03. Reject universal generic store, no new DB/mandatory RDF. |

Conceptual contract (not compiled implementation):
~~~text
Kind (existing stable authority)
TypeDefinition(world,id,version,base_kind,scheme,labels,allowed_parents,policy)
ClassificationFact(id,subject_ref,definition_pin,axis,valid,revision,branch,source)
FieldDefinition(world,id,version,allowed_kinds/profiles,datatype,unit_set,
                cardinality,unknown_policy,visibility)
ValueFact(id,subject_ref,field_pin,value_or_explicit_unknown,context,source)
PredicateDefinition(world,id,version,endpoint_contract,role/lens,
                    direction,cardinality,allowed_epistemic_modes)
WorldRef = ObjectRef | FactRef { world, family, id }
~~~
Do not add these tables or a generic runtime now. Reuse existing Definition, Record/version, shared temporal/branch and query infrastructure as far as compatible. Start with one classification axis or simple multi-valued association; add hierarchy, typed constrained fields only with tested benefit. Need type definition identity/version independently (author metadata, not Concept) and optional explicit reference to in-world concept. Do not infer subtype inheritance of domain facts or enforce exactly one classification unless contract says. Allow deprecated ID to remain valid for old author revisions; explicit changes with new version/migration preview. Unsupported version fails closed. No mandatory fields for partial lore except identity/actual declared validity. Explicit unknown vs missing/unrecorded vs zero; source uncertainty not score. Units type and quantity context required for numerical comparisons; incompatible units fail, conversion declared/versioned only. Explicit qualitative fields valid. Avoid "unknown" default Person. Tag relationships are separate scoped facts where domain needs history.

Fact addressability: compare registry reification of membership/network/parentage vs discriminated reference dispatch. Reification provides one ID resolution route but risks migration/typed-object confusion and duplicate rows. Prefer evaluate minimal tagged WorldRef/FactRef adapters over existing fact family IDs and resolver, canonical specialized storage retained, same world/date/branch/authorization. Need real test that evidence annotations, links, effects and search can target same stable fact after correction/withdrawal, old reference resolves historical context or clearly unavailable. Discriminator and typed lookup disambiguate UUID collision, no fake copy. If unified registry entry warranted, preserve ids with atomic migration and no two canonical sources. Existing scope INV-01/REL/ENT; no new feature created merely for missing addressability. Tagged reference is recommendation, not approved design. Prototype tests original fact id and source only, not full typed annotations.

For compatible general endpoints use allowlisted domain predicate contract (e.g. membership Person or eligible institution to Organization, explicit role; not universal arbitrary edges); typed role distinguishes actor from witness, office holder vs membership, belief vs institution membership. Domain validators keep chronology, ancestry cycles, temporal overlap, cardinality and evidence. Taxonomy cycles rejected only in declared hierarchy with bounded interval intersection; association and cultural descent distinct predicates, no forced transitive causal inference. Validation of canonical mutations uses trusted full author graph; reads scope before traversal/projection/aggregation. No reader leaks from hidden taxonomy class/parent/alias/field/definition/source/edge/cache/facet/errors; same/no-more-powerful ViewContext throughout. No user script/SQL. Cross-world definitions/references require explicit validated import/crossover.
